# `probe/` — the extraction probe harness

Evaluate models on the **real job** — extraction — not the aider coding proxy. The probe
drives a **candidate model** as the extraction agent over a **locked corpus slice** through
the real `write_enrichment` (the fixed Qwen2.5-14B judge gates every record), then scores the
output. Repeatable, isolated, loop-automated — the model_sandbox shape.

## How it works (Decision P1)
`write_enrichment` is a *write boundary*, not an extractor. The **candidate is the variable**:
it reads each chunk and proposes records; `write_enrichment` + the **fixed** judge validate and
store. We score the candidate's extraction, never the judge.

Pointing interface: the candidate emits a **verbatim quote** of the span it grounds on (LLMs
quote far better than they count characters); code locates the quote → char offsets → real
`write_enrichment` slices the bytes from source. The model points, code copies, the judge
checks, the row attests — invariant intact. A corrupted/paraphrased quote fails to locate and
is dropped, never stored.

## Layout
- `run.sh <candidate> [api_alias]` — one candidate over the slice → `results/<label>/`.
- `probe_loop.sh [candidates…]` — swap the lane through candidates (ssh llm-lxc), run, score,
  **always restore `qwen2.5-72b` on a trap**.
- `slice/build_slice.sql` + `slice/chunk_ids.txt` — the locked, frozen test slice (UUIDs only).
- `sql/probe_role.sql` — the scoped `probe` role (**Joe applies** — role/GRANT split).
- `results/<label>/` — `attempts.jsonl`, `run_meta.json`, `scorecard.json`, `isolation.json`.
- `RESULTS.md` — the comparison table + per-model detail (auto-generated by the report module).

The Python lives in `reliquary_enrichment.probe` (importable + unit-tested): `extraction`
(candidate driver), `runner`, `scoring`, `schema` (throwaway probe schema), `cli`, `report`.

## Isolation / safety (non-negotiable — crown-jewel data)
- **Corpus is read-only:** the probe only `SELECT`s `context_reliquary.claim_chunks`.
- **Enrichment writes go to a throwaway `probe_<label>` schema**, created fresh per run and
  dropped after scoring — never prod `enrichment_records`/codex.
- **Scoped `probe` role:** SELECT on `claim_chunks` + CREATE on the db (its own `probe_*`
  schemas only); **no grant on prod enrichment tables** — so the harness *structurally* cannot
  write prod. No prod-write credential ever lives in the harness.
- **Prod-untouched guard:** prod enrichment counts are snapshot before/after and asserted
  unchanged (when readable); the run aborts on any drift.
- **The invariant holds:** the judge gates every record exactly as in prod — grounding is never
  relaxed to score better.

## Scoring (→ `RESULTS.md`)
1. **Grounding pass-rate** — grounded records / proposals that reached the judge (the safety floor).
2. **Cross-context** — Codex entities referenced by records on ≥2 different chunks (v1 proxy for
   stitching the reversal's web; `link_events`/Pass-3 is v2 — Decision P4).
3. **Smoking-gun (decider)** — a *grounded* record on the gold note `89503c71…` capturing the
   B. Smith reversal (actor + reversal + long-COVID/Mental-Health swap).
4. **Throughput** — chunks/min, records/min (wall-clock; logged, not capped).

## Run it
```bash
# one candidate (assumes the api alias is already serving it)
RELIQUARY_ENRICHMENT_PGUSER=probe ... ./probe/run.sh qwen2.5-72b big-thinker
# the full audition (swaps lanes on llm-lxc, restores the default on a trap)
RELIQUARY_ENRICHMENT_PGUSER=probe ... ./probe/probe_loop.sh qwen2.5-72b qwen3-14b
```
